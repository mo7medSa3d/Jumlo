# Supplemental planned contracts

These are planning decisions, not implemented source. All IDs are opaque UUID strings. Root-plan contracts take precedence; these fill the named value types used by the child plans. Each is implemented in its owning interface file unless a task names a separate file.

- `DecodedImage`: `bitmap: Bitmap`, `normalizedExifOrientation: Int`; AutoCloseable releases its bitmap. Color-policy limitations are attached to the job, not invented metadata.
- `PdfInfo`: `pageCount: Int`, `pageBoxes: List<PageBox>`, `hasDigitalText: Boolean`, `capabilities: Set<String>`, `warnings: List<String>`. `PageBox(media: List<Float>, crop: List<Float>, rotationDegrees: Int)` uses four coordinates per box. `PdfInput(file: File, password: CharArray?)` is session-only; `PageCopy(sourceIndex: Int, physicalPageIndex: Int, rotationDegrees: Int)` is zero-based internally. UI physical positions are one-based.
- `ResolvedGeometry`: `sourceCrop: List<Float>` (four normalized coordinates), `outputWidth: Int`, `outputHeight: Int`, `drawRect: List<Float>` (four output-pixel coordinates), `rotationQuarterTurns: Int`, `flipX: Boolean`, `flipY: Boolean`, `matteArgb: Int`. The test helper `outputSize` returns width-to-height. Zero dimensions and invalid normalized rectangles fail before allocation.
- `Preflight`: `finalUrl: String`, `suggestedName: String?`, `mimeType: String?`, `length: Long?`, `acceptsRanges: Boolean?`, `strongEtag: String?`, `lastModified: String?`; absence is unknown, never fabricated successful metadata. Errors are explicit, not default Preflight values.
- `DownloadSettings`: `url: String`, `basename: String?`, `destinationUri: String?`, `wifiOnly: Boolean`, `unmeteredOnly: Boolean`, `cleartextConsent: Boolean`. Saved full signed URLs are sensitive local data: exclude from backups/logs/UI, encrypt with an app-private key when persistence is needed, and otherwise request replacement on restart. Authorization headers remain ephemeral or separately protected, never plain diagnostic fields.
- `DownloadRequest`: settings above, `partialFile: File`, `offset: Long`, `strongEtag: String?`, `lastModified: String?`, `knownTotalBytes: Long?`, and ephemeral request headers. This is execution-only, never serialized as raw File objects.
- `TransferResult`: `status` enum (FINISHED,PAUSED,CANCELLED,RESTART_REQUIRED,FAILED), `bytes: Long`, `totalBytes: Long?`, `strongEtag: String?`, `lastModified: String?`, `errorCode: String?`. FINISHED is transport completion; output verification/publication still follows F03. User-visible completion occurs afterward.
- `EphemeralSecretStore`: `put(secret: CharArray): String`, `consume(handle: String): CharArray?`, `clear(): Unit`; session-only, no serialization/analytics/backup. Introduced with F02 and reused by E06/E24. Handle expiration yields WAITING_FOR_INPUT instead of persisting passwords.
- `VaultSession`: in-memory opaque ID plus expiration monotonic timestamp; never saved. `VaultKeyAccess.authorize(activity, onAuthorized, onError)` drives a real CryptoObject-authenticated unwrap, and cannot be satisfied with a UI boolean. Content uses Tink streaming AEAD only after qualification; file names and metadata are encrypted, while random object ID/version may be AAD. Exported plaintext remains in protected staging until authentication completes for the whole stream. Application relocking drops key/session references; it does not claim guaranteed zeroization of all JVM copies.
- `CodecCapability`: `format: String`, `canDecode: Boolean`, `canEncode: Boolean`, `canPreserveAnimation: Boolean`, `supportedApiRange: IntRange`, `verifiedFixtureIds: List<String>`. No codec is advertised on API levels where its fixture path was not demonstrated.

Test helpers such as textTokens, cornerColor, outputSize and sourceHashesBefore are fixture utilities in the named test source sets, not new application APIs. Assertions in plans are representative expected behaviors; implement test setup in the corresponding Kotlin test class.

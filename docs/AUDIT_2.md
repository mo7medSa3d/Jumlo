# AUDIT_2 — Jumlo evidence-first production audit

Date: 2026-10-28. Baseline: `main` SHA `d599b8a3159f38623e3d0b83c3d58a23073e70cf` (read-only before audit work). **NOT APPROVED FOR PRODUCTION.** This document is an audit, not an assertion of Android/device functionality.

## Evidence standard and status meanings

The 45 IDs below are parsed from `CapabilityRegistry.kt` (44 list entries plus `sha256`). `CapabilityPolicy.kt` classifies navigation-only tools separately. **works** requires a passing tool-specific end-to-end test against the current baseline and validated resulting file; **partial** means a source implementation exists but release-relevant execution or UX requirements lack evidence; **broken** requires a demonstrated failing path; **stub** requires a demonstrated no-op/unimplemented handler. **partial** does not assert that the code crashes. Prior host script checks, Android unit tests, and a green build do not substitute for all 45 tool flows. Since there is no current complete device tool matrix, no tool can honestly be marked works.

Read before product edits: `README.md`, `TEST_REPORT.md`, `AUDIT.md`, `ROUTES.md`, `TOOL_UI_SPEC.md`, `ICON_MAP.md`, `DECISIONS.md`, `CHANGELOG.md`, `IMPLEMENTATION_PLAN.md`, `RELEASE_CHECKLIST.md`. Android-free module boundaries: `core-common`, `downloader-core`, `document-core`, `storage-core` (see README architecture).

## Hardcoded literals, stubs, TODOs, and dead interactions

Source-proven findings (with bounded inspection, **not** a claim of exhaustive repository-wide text search):

1. `MainActivity.kt:64-65` hardcodes active haptics. **Functional** defect relative to the requested settings.
2. `UserPreferencesRepository.kt:143,149,152` hardcodes state overrides for three legacy settings. `setRespectReducedMotion` is currently a write with no observable effect; Wi-Fi/concurrency writers are obsolete.
3. `ScanScreen.kt:95,99` uses fixed paper/checkerboard greys, and `:152` uses fixed ink swatches. Canvas/document colors may be intentional; assess contrast separately and do not blindly replace content colors with UI theme colors.
4. `Color.kt:14-85,125+` defines centralized token colors; these are *expected* token constants, not evidence of uncontrolled screen-local hardcoding. Full light/dark AA remains unverified.
5. `PdfViewerScreen.kt:394,436`, `PrintScreen.kt:538`, `MediaWorkspace.kt:400` construct numerals/units inline. Check Arabic bidi/digit presentation; values and units themselves are not proof of unlocalized English.
6. `TOOL_UI_SPEC.md:3` claims 47 registry entries while `CapabilityRegistry.kt:7-59` contains 45; the current documentation inventory must be corrected.
7. `TOOL_UI_SPEC.md` describes availability as 44 enabled/3 disabled but all **45 current registry IDs** are marked visible/enabled by `CapabilityPolicy.kt:20-46`. Superseded descriptions must be labelled historical.
8. `.github/workflows/ci.yml:68-75` runs `lintDebug` and `verifyCompactApkSize`, **not** `lintRelease` or `verifyReleaseApkSize` in the automatic main build. Device tests run only on manual `workflow_dispatch` input at lines 193-221. Add mandatory gates without removing any existing protection.
9. `DECISIONS.md` explicitly documents prior `webpage_pdf` / `xf_05` removals for missing handlers. Those are not present in today's 45-tool catalogue and must not be falsely counted as newly found live stubs.
10. Known screenshot gap: `CHANGELOG.md:135` discloses a Compare Images heading-only preview on the earlier screenshot matrix. Reproduce on the current source before attributing a cause.

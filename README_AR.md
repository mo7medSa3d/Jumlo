# جملو (Jumlo) — سورس أندرويد 2026

هذا الإصدار يضيف علامة Jumlo وأيقونات جديدة ورسوم حركة Spring وتفاعلات لمس وأصوات واجهة صغيرة، مع الحفاظ على معرف التطبيق `com.jumlo.app` وقاعدة البيانات والروابط القديمة لحماية الترقية. يشمل السورس ملفات أيقونات قابلة للاستخدام في iOS **ولا يحتوي على تطبيق iOS**. اختبارات Host وملفات الموارد ناجحة، لكن لم يتم بناء APK أو تجربة جهاز أو قياس الأداء، ولذلك **الإصدار ليس معتمداً للنشر**. راجع `docs/JUMLO_2026_MOTION_BRAND_QA.md`.

# Jumlo — دليل السورس المحدّث

## حالة النسخة المحدثة - 17 أكتوبر 2026

هذه نسخة سورس للتجربة والمراجعة فقط وليست جاهزة للنشر. نجحت اختبارات Host
(117 Kotlin، و8 Media، و10 SQLite، و14 فحص موارد)، لكن **لم يتم بناء تطبيق
Android** بسبب عدم توفر Android SDK وGradle 8.14 وعدم إمكانية تنزيله.
الميزات الحساسة وتنزيل الوسائط ما زالت مقفولة لحين فحوص الأجهزة والتراخيص.
راجع `verification/current-session/followup-2026-10-17/REPORT.md` و`docs/RELEASE.md`.

هذا التسليم يطبّق خطة تطوير Jumlo على ملف السورس المرفق، مع الإبقاء على Kotlin وJetpack Compose وRoom وWorkManager ومحركات معالجة الملفات الأصلية. مصدر العمل هو ملف ZIP المرفق، ولا يفترض هذا التقرير أنه مطابق لآخر نسخة من فرع GitHub.

## أهم التعديلات

- إعادة تنظيم Home وTools وFiles وDownloads ومساحة العمل في شاشات ومكونات منفصلة، مع صفوف ملفات وقوائم إجراءات وواجهة أقل ازدحامًا.
- تحويل Account & Data إلى مساحة محلية حقيقية، تضم الملفات والتخزين المقاس والإعدادات والخصوصية والمساعدة؛ وإزالة الهوية والاشتراك الوهميين.
- إعدادات مجمعة تحفظ الخيارات، وتراعي العربية والإنجليزية واتجاه العرض والثيم وتقليل الحركة والاستجابة اللمسية.
- اختصارات رئيسية قابلة للتخصيص والترتيب والحفظ محليًا، وتخطيط يأخذ حدود مفصل الشاشة القابلة للطي في الحسبان.
- سياسة موحدة للأدوات في الواجهة وعند إرسال المهمة وتنفيذها. الكتالوج يضم **33 مدخلًا: 32 أداة معالجة وعارض PDF**؛ ويُحسب العدد من الأدوات المتاحة فعليًا. تبقى تسع إمكانات غير مؤهلة محجوبة، بما فيها الحذف الحساس داخل PDF والحماية والتشفير وDrive والميديا الاختيارية وOCR والتقاط صفحات الويب.
- فصل الحفظ الصريح للمسودة عن الاستعادة التلقائية، ومعالجة الحفظ والتراجع والعودة وإعادة المحاولة ومنع تكرار الطلب نفسه. كلمات المرور وروابط التنزيل السرية لا تحفظ في المسودات الدائمة.
- تأكيد الحذف النهائي لمجموعة محددة من عناصر سلة التطبيق؛ وتنظيف الكاش القابل لإعادة الإنشاء فقط، مع الحفاظ على المدخلات والنتائج والملفات المرحلية والتنزيلات القابلة للاستئناف.
- إصلاحات لاختلافات أسماء Unicode، وتصادمات الأرشيفات، واستئناف التنزيل بعد انقطاع الكتابة، والتحقق من بايتات النتائج وبصمتها قبل إعلان النجاح أو إعادة تصديرها.
- معاينة الأسماء المقترحة قبل إعادة التسمية، وإظهار إجراءات الملفات حسب الصلاحيات الفعلية، ومنع إرسال مهام العلامة المائية أو التعليق بلا المحتوى المطلوب.
- إصلاح تنظيم إضافات Gradle وإعادة تفعيل وحدة benchmark، واستخدام توقيع Debug القياسي، والاحتفاظ بتحسينات R8 وفحوص الاختبار وlint.

## فتح المشروع وتشغيله

افتح المجلد الذي يحتوي على `settings.gradle.kts` في Android Studio. يلزم JDK 17 وAndroid SDK 36 وBuild Tools 36.0.0. يدعم التطبيق API 26 فأعلى، ويستهدف API 36. استخدم Gradle Wrapper الموجود في المشروع:

```bash
bash scripts/restore-wrapper.sh --check
./gradlew :app:assembleDebug --no-daemon --console=plain
./gradlew :app:testDebugUnitTest --no-daemon --console=plain
./gradlew :app:lintDebug --no-daemon --console=plain
```

لتشغيل بوابات البناء المتتابعة مع حفظ كل نتيجة منفصلة:

```bash
bash scripts/verify-native.sh gate
```

اختبارات محركات الملفات على الكمبيوتر تستخدم Kotlin 2.0.21 وJDK وPython، وبعض اختبارات الميديا تحتاج FFmpeg. اختبارات HTTP المحلية تستخدم خادمًا على loopback:

```bash
bash scripts/verify-host.sh
bash scripts/test-workspace.sh
bash verification/production-2026-10-17/ui/run-home-layout-tests.sh
python3 scripts/test-media-ffmpeg.py
python3 scripts/generate-feature-matrix.py
```

## كيف تقرأ نتائج التحقق؟

الأوامر التي شُغّلت ونتائجها الفعلية موثقة في [دليل الإصدار](docs/RELEASE.md)، والتقارير والسجلات في `verification/production-2026-10-17/`. اختبارات JVM والملفات على الكمبيوتر ليست بديلًا عن تشغيل التطبيق على Android؛ كما أن وجود كود اختبار instrumentation لا يعني أنه نجح على جهاز.

تمت مراجعة إصلاحات التكامل بصورة مستقلة، مع الاحتفاظ بنتائج الاختبارات الناجحة والإخفاقات التي ظهرت أثناء التشخيص وأسباب علاجها. راجع [التدقيق](AUDIT.md)، و[مصفوفة الأدوات](docs/FEATURE_QUALIFICATION_MATRIX.md)، و[الشاشات والإجراءات](docs/SCREEN_AND_ACTION_MATRIX.md) لمعرفة نطاق كل دليل.

## شروط النشر المتبقية

هذا ملف سورس مع تقارير تنفيذ وتحقق، وليس اعتمادًا نهائيًا للنشر على المتجر. يلزم تشغيل اختبارات API 26 وAPI 36، وتجربة الترقية من تثبيت تاريخي حقيقي، ومراجعة الواجهات بالعربية والإنجليزية والثيمين وحجم خط 200% وإمكانية الوصول، وقياس الأداء على جهاز فعلي، ثم توقيع الإصدار بمفتاح المالك وتشغيل CI على الـSHA المراد نشره.

لم يُعثر على ملف Room v1 تاريخي موثوق في المصدر أو المسارات التاريخية المفحوصة. لذلك أضيفت عينة SQL هيكلية موضّحة الأصل لاختبار حفظ البيانات وبنية الترحيل، ولم تُختلق هوية لقاعدة قديمة. التفاصيل في [توثيق أصل الـschema](app/schemas/schema-provenance.md).

لا يتضمن الأرشيف مفاتيح توقيع خاصة أو SDK أو كاش البناء أو حزم التطبيق الناتجة. يتضمن `CONTENTS_SHA256.json` بصمة وحجم كل ملف، وجرى تصميم أداة التغليف لإعادة فتح ZIP والتحقق من CRC والبصمات بعد كتابته.
